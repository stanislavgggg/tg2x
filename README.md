# tg2x — Telegram-канал → X (Twitter)

Слушает канал Coinplay, берёт пост (картинка + длинный текст), ужимает текст
через LLM до одного твита и публикует в X вместе с картинкой.
По желанию — с ревью-кнопками в Telegram перед публикацией.

Тот же паттерн, что и в `scraper-tg-threads`: Railway + Telethon (юзер-сессия) +
SQLite на Volume + фоновый воркер. Отдельный сервис, работающий esports-пайплайн
не трогает.

```
канал Coinplay ──Telethon──► SQLite ──LLM──► черновик ──ревью в TG──► X
```

## Что делает по шагам

1. **Слушатель** ловит новые посты канала, качает фото, складывает в `raw_messages`.
   Альбом (несколько фото одним постом) собирается в одну запись: текст берётся
   самый длинный из пачки, картинка — первая.
2. **Фильтры** отсекают посты без картинки, слишком короткие и со стоп-словами.
3. **Переписывание**: LLM получает исходный текст и правила, возвращает одну фразу.
   Сверху навешиваются хештеги и ссылка — ровно столько, сколько влезает в 280.
4. **Ревью** (если включено): черновик уходит боту в Telegram с кнопками
   ✅ Опубликовать / 🔄 Переписать / 🚫 Пропустить. Можно ответить на сообщение
   своим текстом — он заменит черновик и сразу уйдёт в публикацию.
5. **Публикация** в X: картинка через media upload v1.1, твит через API v2.

## Промпт переписывания

Живёт в `rewriter.py` (`SYSTEM_PROMPT`). Главные правила уже заложены:

- ровно один твит, без тредов и вариантов;
- цифры, суммы бонусов, названия команд, турниров и время — только как в источнике,
  ничего не выдумывать и не округлять;
- что не влезает — выбрасывать, а не сжимать в неточную формулировку;
- без хештегов и ссылок в теле (они добавляются отдельно, чтобы точно считать лимит);
- максимум один эмодзи, и только если он был в источнике;
- язык — как в исходном посте.

Тон правится через переменную `BRAND_VOICE` без залезания в код.

Провайдер переключается переменной `LLM_PROVIDER`: `openai` (по умолчанию),
`anthropic` или `openrouter`. Ключ один и тот же — `LLM_API_KEY`, подставляется
от выбранного провайдера. Задача здесь простая (ужать готовый текст), поэтому
мелкой модели хватает: `gpt-4.1-mini` на объёме 1-3 поста в день стоит центы в месяц.

## Переменные окружения

Полный список — в `.env.example`. Обязательный минимум:

| Переменная | Что это |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | с https://my.telegram.org |
| `TELEGRAM_STRING_SESSION` | результат `python gen_session.py` локально |
| `SOURCE_CHAT` | id канала (`-100...`) или `@username` |
| `X_API_KEY`, `X_API_SECRET`, `X_ACCESS_TOKEN`, `X_ACCESS_SECRET` | блок **OAuth 1.0a**, права Read and write |
| `LLM_API_KEY` | ключ OpenAI (по умолчанию), либо Anthropic/OpenRouter — см. `LLM_PROVIDER` |
| `REVIEW_BOT_TOKEN`, `REVIEW_CHAT_ID` | если `REVIEW_ENABLED=true` |
| `DATA_DIR=/data` | Railway Volume |
| `ADMIN_TOKEN` | пароль для `/admin/*` |

Полезные необязательные:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `X_LINK` | пусто | ссылка в конец твита, считается как 23 символа |
| `X_HASHTAGS` | пусто | `#crypto #casino` или `crypto, casino` |
| `REQUIRE_MEDIA` | `true` | посты без картинки не берём |
| `SKIP_IF_CONTAINS` | пусто | стоп-слова через запятую |
| `ONLY_IF_CONTAINS` | пусто | брать только посты с этими словами (например `Premier League, PGL`) |
| `POST_DELAY_SECONDS` | `0` | пауза перед публикацией после одобрения |
| `REVIEW_TIMEOUT_SECONDS` | `0` | автопубликация, если не нажали кнопку; `0` = ждать |
| `DRY_RUN` | `false` | всё считает, но в X не постит — для первого запуска |
| `LLM_PROVIDER` | `openai` | `openai` \| `anthropic` \| `openrouter` |
| `LLM_MODEL` | `gpt-4.1-mini` | любая модель выбранного провайдера |

## Запуск на Railway

1. **Сессия Telegram.** Локально: `pip install telethon`, `python gen_session.py`.
   Скрипт напечатает строку сессии и список каналов с их id — оттуда берём `SOURCE_CHAT`.
   Аккаунт должен быть подписан на канал (или быть его админом).
2. **Ключи X.** Developer Portal → приложение → User authentication settings →
   права **Read and write** → и только после этого Keys & Tokens → **OAuth 1.0a**
   Consumer Keys + Access Token/Secret. Если токены выпущены до смены прав —
   перевыпустить, иначе постинг будет отдавать 403.
3. **Бот для ревью.** @BotFather → новый бот → токен. Свой `chat_id` — у @userinfobot.
   Если пишете в группу, добавьте бота в неё и возьмите id группы (`-100...`).
   Бот должен быть свободен от webhook — сервис использует getUpdates.
4. **Railway**: новый сервис из репозитория, Volume смонтировать в `/data`,
   заполнить переменные, задеплоить.
5. **Проверка**: `GET /status` — счётчики и последние посты.
   `POST /admin/backfill?token=...&limit=3` — забрать последние 3 поста канала
   и прогнать их через пайплайн, не дожидаясь нового поста в канале.

Первый прогон имеет смысл делать с `DRY_RUN=true` — тексты будут видны в ревью
и в `/status`, но в X ничего не уйдёт.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | пинг |
| GET | `/status` | счётчики по статусам + 20 последних постов |
| GET | `/admin/dialogs?token=` | список диалогов, чтобы найти id канала |
| POST | `/admin/backfill?token=&limit=3` | забрать последние N постов канала |
| POST | `/admin/requeue/{id}?token=` | переписать и провести пост заново |
| POST | `/admin/skip/{id}?token=` | снять пост с публикации |

## Статусы поста

`pending` → `review` → `approved` → `posted`
Плюс `skipped` (фильтр или кнопка) и `failed` (кончились попытки, `MAX_ATTEMPTS`).

## Что важно знать

- **Volume обязателен.** Без него при каждом редеплое теряются БД и скачанные
  картинки, и канал переедет заново — часть постов может уйти повторно.
- **Только фото.** Видео и документы в X не грузятся (нужен chunked upload);
  такой пост либо уйдёт без картинки, либо отфильтруется при `REQUIRE_MEDIA=true`.
- **Ссылка съедает 23 символа** в лимите 280 независимо от своей длины — это
  учтено при сборке твита, тело режется под остаток.
- **X тарифицирует постинг** по своему тарифу аккаунта — на объёме канала
  (1-3 поста в день) это копейки, но следите за лимитами приложения.
- **Дубли.** Уникальность по `(chat_id, msg_id)` и `(chat_id, group_key)` —
  один и тот же пост дважды не опубликуется даже при рестарте.

## Версия Python

Проект зафиксирован на Python 3.12 через файл `.python-version`. Причина: в 3.13
из стандартной библиотеки убрали модуль `imghdr`, а `tweepy` его использует для
загрузки картинок в X — на 3.13 сборка падает с `ModuleNotFoundError: No module
named 'imghdr'`. Не удаляйте этот файл при обновлении зависимостей.
